# Security

## Секреты

Передавайте ключи только через environment variables или secret storage CI.
Не добавляйте `.env`, API keys и registry credentials в репозиторий или артефакты.
`DEEPSEEK_API_KEY`, `SCA_LLM_API_KEY`, `DEPENDENCY_TRACK_API_KEY` и
`SCA_API_TOKEN` не должны попадать в параметры командной строки.

## Доверительная граница

Container images, SBOM, VDR и vulnerability rules считаются недоверенными
входными данными. Анализатор не запускает entrypoint образа. On-prem сервису нужен
доступ к Docker socket; разворачивайте его на выделенном runner/host в доверенной
сети и ограничивайте доступ bearer token и сетевой политикой.

Исходники сканируются пассивно через Syft. Сборщики автоматически не запускаются.
Registry credentials должны быть настроены на runner/host, не в JSON задания.

LLM получает только структурированное резюме расхождений и findings. Внешний вызов
выполняется только с `--with-llm`. Ответ модели не может автоматически подавить
finding.

## Сообщение об уязвимости

Не публикуйте сведения об уязвимости в открытом issue. Используйте GitHub Private
Vulnerability Reporting в разделе Security репозитория. Укажите версию, входные
данные без секретов, ожидаемое и фактическое поведение.

## Удалённые входы

API v2 выключен без SCA_API_TOKEN или SCA_API_TOKEN_FILE. Списки разрешённых
TeamCity/Bitbucket/Nexus host[:port] задаются эксплуатацией. Не включайте
произвольные недоверенные hosts в эти списки. API-клиент получает доступ
к ресурсам в пределах прав настроенных на сервисе credentials.

Токены TeamCity/Bitbucket можно передавать через *_FILE, смонтированные read-only.
Git headers передаются в окружении процесса, а не в аргументах или config checkout.
Raw Git stderr и тело HTTP-ошибки артефакта не публикуются в статусе задания.
TLS-проверка обязательна, redirects выключены. Корпоративные CA передаются
через SCA_CA_BUNDLE; CA Nexus настраивается на Docker daemon отдельно.

Входящий TLS, лимит размера HTTP-запроса и rate limiting настраиваются на reverse
proxy. Очередь в памяти сервиса не имеет отдельной квоты. В рабочем каталоге
сохраняются отчёты с именами пакетов, путями и корпоративными URL; доступ к нему
и сроки хранения должны соответствовать правилам компании.

Compose не публикует API во внешнюю сеть по умолчанию. Секретные каталоги,
Docker credentials и .env исключены из Git и build context.
