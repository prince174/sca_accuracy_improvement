# Evidence и сравнение модели — 19 сентября 2026

База создана и наполнена. Текущий выбор изменений моделью не показал преимущества
перед применением тех же допустимых операций кодом. Ниже разделены два эксперимента;
их нельзя смешивать в оценку качества на production-проектах.

## Что выполнено

- PostgreSQL, хранение файлов по SHA-256, поиск, API и история разметки.
- 588 синтетических случаев: 196 сочетаний экосистемы/сценария, три варианта имён.
- 196 случаев рассмотрены в живом режиме, из них 124 имели кандидатов и вызвали
  `deepseek-v4-flash` через DeepSeek API. Остальные 72 не требовали решения модели.
- Ещё 392 варианта прошли детерминированное сравнение без вызова API.
- Шесть scratch-образов с известными package metadata действительно собраны и
  просканированы Syft через работающий HTTP-сервис. Целевые контейнеры не запускались.
- Для трёх из этих образов отдельно вызвана модель с настоящими evidence сканера.
- Всего 127 вызовов модели в этих двух экспериментах; ошибок API/контракта не было.

Модель не видела эталонный состав или название сценария. Во всех сравнениях
`allowed_rules` и модель используют одинаковых кандидатов и один валидатор.

## Синтетические наблюдения: 124 случая с реальным вызовом модели

| Режим | TP | FP | FN | Неразрешённые идентичности |
|---|---:|---:|---:|---:|
| Старое обогащение (`legacy_rules`) | 135 | 51 | 27 | 12 |
| Все допустимые изменения без LLM (`allowed_rules`) | 162 | 50 | 0 | 12 |
| DeepSeek + тот же валидатор | 109 | 50 | 53 | 12 |

Модель не снизила FP по сравнению с равным ей по возможностям вариантом без LLM,
но пропустила 53 известных компонента. Принято 84 операции, отложено 54; отклонённых
валидатором и нерассмотренных решений нет. Одно отложенное добавление избыточно
после замены идентичности, поэтому число отложенных решений не равно числу FN.

Примеры причин: модель считала `synthetic-package-metadata` недостаточно сильным
источником, требовала дополнительный хеш/lock-файл либо откладывала добавление
наблюдаемой версии из-за конфликта с исходной. Недоверенный текст в пути тоже
приводил к отказу от добавления, хотя эталон говорил о наличии пакета.

Это показывает чувствительность к описанию evidence и излишнюю осторожность
относительно данного эталона. Мы не меняли prompt по ходу прогона и не подгоняли
ожидания под ответ модели. Влияние одного названия источника отдельно не изолировано:
для причинного вывода нужен парный эксперимент с изменением только этого поля.

API token и пароли находятся только в исключённом из Git `.env`.

## Ограничения и следующий проверяемый вопрос

В этом наборе все разрешённые сильные кандидаты соответствуют эталону. Поэтому
применение всех кандидатов — сильная контрольная стратегия, а возможная польза
модели при ложных сильных свидетельствах здесь не измеряется. Копии имён не являются
независимыми реальными сборками. Метрики считаются по PURL, не по CVE или вызовам кода.

Доказательств пользы модели как обязательного фильтра пока нет. Следующий полезный
набор должен содержать проверенные ошибки идентификации сканера и противоречивые
свидетельства реальных поставок. Решения модели нужно сравнивать на отложенном
наборе с тем же детерминированным валидатором. Настройки рабочего API этим
экспериментом не изменены.
