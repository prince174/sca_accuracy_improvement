# Улучшение контекста evidence — 21.09.2026

Исправлена потеря исходных признаков идентификации между Syft и запросом модели.
Раньше модель видела scanner label, путь и confidence, но не видела manifest и
Maven metadata, из которых возникла идентичность. Ложный `api:api@2.0.16`
получил 75% и прошёл фильтр в [предыдущем прогоне](scoring-acceptance.md).

Теперь передаются выбранные поля metadata с provenance, хешем исходного
metadata-record и явными ограничениями полноты. В каждую запись включены
связанные наблюдения того же образа: другие идентичности в том же файле и
другие версии того же пакета. Они сохраняются при разделении запроса на порции
и имеют собственный evidence ID этой записи. Это позволяет сравнивать признаки
и корректно цитировать основание, не используя чужой ID.

Изменение не содержит исключений для SLF4J, `api:api` или конкретной экосистемы
в фильтре: все компоненты по-прежнему оценивает модель, код применяет TP >70.
Соседство в одном файле не является автоматическим основанием удаления.
Запрос ограничен 40 компонентами и 96 000 байтами JSON; усечение проекции
metadata и списка связанных наблюдений отмечается явно.

## Проверка на прежних входах

Выполнены два полных повтора на трёх образах. Использовались сохранённые image
digest и исходные SBOM из `out/scoring-service-live-2`, без пересборки.
Совпадение digest, сохранность оригинала и полнота оценок проверены скриптом.
Сервис обращался к тому же настроенному DeepSeek API. Пример команды:

```bash
uv run --env-file .env python golden/evidence/verify_scoring_service.py \
  --live --baseline out/scoring-service-live-2 \
  --output out/scoring-evidence-context-1
```

Второй результат: `out/scoring-evidence-context-2`. Каждый каталог содержит
`acceptance.json` и полные запросы, ответы, оценки и отчёты по каждому случаю.

| Случай | До: FP / FN | Повтор 1: FP / FN | Повтор 2: FP / FN |
|---|---:|---:|---:|
| Java: SLF4J 2.0.16 | 1 / 0 | 0 / 0 | 0 / 0 |
| npm: версия 1.0.0 | 0 / 0 | 0 / 0 | 0 / 0 |
| npm: одновременно 1.0.0 и 2.0.0 | 0 / 0 | 0 / 0 | 0 / 0 |

Ложный `api:api` получил 15 и 10; настоящий SLF4J — 90 в обоих повторах.
В объяснении модель сопоставила manifest SLF4J с embedded Maven coordinates
в том же JAR и оценила альтернативный label как alias, а не отдельную библиотеку.
Обе реальные версии npm сохранены. Ошибок контракта в этих шести ответах не было.
Все шесть выходных файлов прошли CycloneDX CLI 0.33.1 `validate --fail-on-errors`;
хеши файлов оценок совпали с evidence-хранилищем, записи помечены synthetic.

## Пределы результата

Это регрессионные примеры, использованные при разработке исправления, а не
независимый набор для оценки production-качества. Одновременно изменены контекст
и инструкция модели; отдельно вклад каждого фактора не измерялся. Поле image
в повторных запросах содержит digest вместо прежнего тега. Проценты остаются
некалиброванными: например, оценки отсутствующего пакета менялись, хотя решение
фильтра сохранялось. Исходные metadata могут быть ложными или устаревшими;
их наличие и хеш не доказывают присутствие соответствующего кода. Для оценки
обобщения нужен отдельный набор настоящих сборок с проверенной разметкой.
