# Выбор модели для сверки SBOM

Проверено 19 сентября 2026. Специализация на cybersecurity не равна обучению
сверке CycloneDX, файлов образа и исходников. В рассмотренных первичных источниках
не найден готовый локальный checkpoint с опубликованной оценкой именно этого контракта.
Это результат ограниченного поиска, не утверждение об отсутствии таких моделей вообще.

| Кандидат | Опубликованная специализация | Что проверять у нас |
|---|---|---|
| [Foundation-Sec-8B-Reasoning, Cisco](https://huggingface.co/fdtn-ai/Foundation-Sec-8B-Reasoning) | Security triage, CTI, классификация и reasoning; 8B, локальный запуск | Решения по противоречивым evidence, JSON-контракт; CTI-оценки не измеряют точность состава образа |
| [VulnLLM-R-7B](https://huggingface.co/Virtue-AI-HUB/VulnLLM-R-7B) | Поиск уязвимостей через анализ кода, потоков данных и управления | Перспективнее для последующего анализа конкретного кода, чем для восстановления package identity |
| [Qwen3-Coder-30B-A3B-Instruct](https://huggingface.co/Qwen/Qwen3-Coder-30B-A3B-Instruct) | Работа с кодом и контекстом репозитория; 30.5B всего, 3.3B активных параметров | Базовый локальный кандидат для разбора manifest/lock/metadata; превосходство в SCA не установлено |
| DeepSeek Flash / V4 Pro | Универсальные модели, существующий API | Доступное сейчас парное сравнение без загрузки весов на рабочую машину |

Веса специализированных моделей не скачивались, новые провайдеры не подключались.
При появлении локального endpoint тот же набор запускается через OpenAI-compatible API.
Версии весов, quantization и serving runtime нужно фиксировать отдельно: ответ API
может вернуть только псевдоним, а не неизменяемую ревизию модели.

## Существенное изменение DeepSeek

[Официальная документация](https://api-docs.deepseek.com/) сообщает, что старое имя
`deepseek-v4-flash` теперь направляется на V4.1-Flash. Поэтому прошлые результаты
нельзя приписывать исходным весам V4 только по имени в запросе.
[Thinking mode](https://api-docs.deepseek.com/guides/thinking_mode/) включён по умолчанию;
в этом режиме `temperature` игнорируется. Сервис сохраняет requested/reported model,
fingerprint при наличии, настройки, расход токенов и длительность в `_transport`.
Цепочки внутренних рассуждений не сохраняются. Отсутствующий fingerprint не выдумывается.

`SCA_LLM_THINKING=enabled|disabled`, `SCA_LLM_REASONING_EFFORT=low|high|max`,
`SCA_LLM_MAX_TOKENS` задаются только для endpoint, который их поддерживает.
Пустые значения сохраняют настройки провайдера; JSON mode по-прежнему обязателен.
Обрезанный по лимиту ответ отклоняется до применения изменений.

## Диагностика предыдущих пропусков

```sh
uv run --env-file .env python -m sca_accuracy.experiments --pro --limit 8 --max-calls 40
```

В `out/ablation-v1/omissions.json` попадает весь разбор добавочных FN.
Выборка для парного эксперимента содержит сначала разные семейства прежних ошибок,
затем оставшиеся ошибки в порядке исходного отчёта. Это диагностический набор,
не контрольная оценка общего качества. Один фактор относительно baseline меняется
за раз: только название источника evidence, только уточнение prompt, thinking,
либо модель Pro. Название источника меняется **только внутри эксперимента**;
синтетические свидетельства не выдаются за настоящий результат Syft.
Кандидаты и валидатор остаются исходными. Результаты старого запуска не подменяются.

Сравнение использует только полные пары; ошибки API выводятся отдельно.
Запросы/ответы кешируются по фактам, prompt, настройкам и версии клиента.
Кеш фиксирует исторический ответ, но не гарантирует воспроизведение весов API.
Количество вызовов ограничено до запуска. Денежная стоимость не выводится из числа
токенов без тарифа и учёта кеша провайдера; сохранён `usage` для последующего расчёта.

Рекомендация: выбирать по FP/FN и проверке основания каждого изменения на отдельном
наборе поставок. CTI, SAST и coding benchmarks полезны для выбора кандидатов,
но не заменяют такой тест. Дообучение имеет смысл после появления проверенной
разметки спорных случаев; ответы самой модели не становятся эталоном.
