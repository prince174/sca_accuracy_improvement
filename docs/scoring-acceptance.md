# Проверка фильтра TP >70% — 21.09.2026

Проверена политика `tp-score-gt-70-v1` через работающий Linux HTTP-сервис,
Syft 1.51.1, DeepSeek API и PostgreSQL evidence-хранилище. Запрошенная модель
`deepseek-v4-flash`, в ответах API — `deepseek-flash`. Контейнеры анализируемых
образов не запускались. Исходные SBOM в этой проверке специально созданы
конструктором с ошибочными записями; это не новые SBOM Maven-плагина.

## Полный прогон

Команда: `uv run --env-file .env python golden/evidence/verify_scoring_service.py
--live --output out/scoring-service-live-2`.

| Образ | Оценено идентичностей | Включено | Исключено | FP относительно конструктора | FN |
|---|---:|---:|---:|---:|---:|
| Java: оригинальный slf4j-api 2.0.16 | 4 | 2 | 2 | 1 | 0 |
| npm: версия 1.0.0 | 3 | 1 | 2 | 0 | 0 |
| npm: одновременно 1.0.0 и 2.0.0 | 4 | 2 | 2 | 0 | 0 |

Во всех трёх заданиях итоговый состав точно соответствует правилу TP >70;
сохранены все оценки и оригиналы. SHA-256 файла оценок совпал с записью в БД.
Все три выходных SBOM прошли `cyclonedx/cyclonedx-cli:0.33.1 validate
--fail-on-errors`. HTML-таблица и раскрытие оснований проверены в браузере.

В Java-примере модель исключила заявленную версию `slf4j-api@2.0.13` с баллом
20 и отсутствующий npm-пакет с баллом 10, включила реальный `slf4j-api@2.0.16`
с баллом 95. Однако дополнительная ошибочная идентичность сканера
`pkg:maven/api/api@2.0.16` получила 75 и тоже прошла порог. В обоих npm-примерах
выход совпал с известным составом конструктора; реально поставляемые версии
получили по 90.

## Первый прогон также сохранён

В `out/scoring-service-live` сохранён первый Java-результат: тот же ложный
`api:api` получил 95, реальный SLF4J — 98. Следующее npm-задание завершилось
ошибкой `Assessment references unknown evidence`; сервис не выдал SBOM.
Проверка скачивания результата этого failed-задания вернула HTTP 409.
Первый скрипт остановился на ошибке; после исправления скрипта для сохранения

## Что подтверждено

163 автоматических теста проверяют ядро и API, включая строгую границу 70,
неполные/некорректные оценки, сохранение вложенных компонентов, очистку ссылок
и безопасное отображение текста модели. Фильтр действительно изменяет SBOM.
Валидатор проверяет формат, полноту и принадлежность ссылок, но не истинность
баллов. Наблюдённый FP и различие 95/75 показывают, что некалиброванные проценты
модели не обеспечивают гарантированную точность. Следующее улучшение качества
должно проверяться на отдельных размеченных сборках и конкурирующих
идентичностях одного файла, без подгонки оценок под эти три примера.

Прерванный 19.09 прогон большого golden-образа (246 идентичностей) не получил
итогового результата и не учитывается как успешная проверка.
